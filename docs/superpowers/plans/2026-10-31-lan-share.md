# LAN Share Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Share files between Windows and Android devices over the LAN via right-click/Share sheet, a QR code, or a nearby-sender list.

**Architecture:** A Dart core library (token, pairing, sender server, discovery, receiver client) is built and tested first, with no UI. Flutter UI and thin native glue (Windows shell entry, Android share intent) sit on top. The sender hosts a temporary TLS server; receivers are the app or a plain browser.

**Tech Stack:** Flutter/Dart (`shelf`, `cryptography`, `multicast_dns`, `qr_flutter`, `mobile_scanner`, `receive_sharing_intent`), Windows shell verb (registry), Android intent filters.

**Spec:** `docs/superpowers/specs/2026-10-31-lan-share-design.md`

## Global Constraints
- Token: single-use, expires after 5 minutes.
- Server idle shutdown: ~5 minutes; stops on transfer complete.
- Pairing code: 4 digits, shown on both screens; mismatch refuses transfer and closes session.
- Server serves only the selected files; no directory access.
- No accounts, telemetry, or external network calls. No plain-HTTP fallback.
- UI labels 1-3 words, no instructional text; icons, colour, progress ring.
- Platforms: Windows, Android only.

## Review Focus
- Filename `../../x.txt` or `C:\evil.exe` from sender: receiver saves inside target folder only, sanitized.
- Two selected files with the same name: both are delivered, second renamed `name (2).ext`.
- Machine with VPN/virtual adapters: QR uses the real LAN address, not a virtual one.
- File deleted or locked mid-transfer: clear failed state with retry, server stays safe.
- Multi-GB file: streamed, never fully loaded into memory.
- Unicode/space/emoji filenames survive the round trip.
- Port already in use: server picks another free port.
